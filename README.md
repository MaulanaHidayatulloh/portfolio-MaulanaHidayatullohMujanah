## 🚀 Running Locally

Because this is a static website, no backend server or package installation is required.

### 1. Clone or download the project

```bash
git clone https://github.com/MaulanaHidayatulloh/portfolio-MaulanaHidayatullohMujanah.git
cd portfolio-MaulanaHidayatullohMujanah
```

### 2. Open the website

The simplest option is to open:

```text
index.html
```

directly in a browser.

For a development environment, you can also use a local static server such as VS Code Live Server.

## 🌍 Deploying to GitHub Pages

This project is suitable for GitHub Pages because it consists of static HTML, CSS, JavaScript, images, and documents.

Typical deployment steps:

1. Push the project to a GitHub repository.
2. Open the repository's **Settings**.
3. Open **Pages**.
4. Select the branch containing the website.
5. Select the root directory (`/`).
6. Save the GitHub Pages configuration.
7. Wait for GitHub Pages to publish the site.

The portfolio currently uses the GitHub Pages URL:

```text
https://maulanahidayatulloh.github.io/portfolio-MaulanaHidayatullohMujanah/
```

## ❓ About `404.html`

`404.html` is a custom error page for URLs that do not exist.

It does **not** need to be linked from `index.html`.

When the website is hosted on GitHub Pages and a visitor opens a missing route, GitHub Pages can serve `404.html` automatically. For example:

```text
/portfolio-MaulanaHidayatullohMujanah/example
```

can display the custom 404 page instead of a generic browser/server error.

The current page provides:

- A `404` status message
- A "Page Not Found" heading
- A short explanation
- A button to return to the homepage

> **Note:** The current `404.html` uses `href="index.html"` for the Back to Home button. This works for common one-level missing paths, but using the GitHub Pages project root URL is more robust for deeply nested missing paths.
